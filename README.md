# HolyBible

Интерактивный проводник по Библии и христианской культуре: Flutter, iOS и
Android, офлайн-first. Текст — главное, всё остальное раскрывается по тапу.
Приложение работает без сети целиком: перевод, поиск, справочник людей и мест,
карта, календарь и словарь оригинала лежат в базе внутри бандла.

Этот файл — вход для того, кто открывает репозиторий впервые. Дальше:

- [docs/vision.md](docs/vision.md) — исходное задание, записанное заказчиком
  дословно. От него меряется всё остальное.
- [docs/roadmap.md](docs/roadmap.md) — что сделано, по датам и по пунктам ТЗ,
  и что в очереди. Обновляется по мере закрытия пунктов.
- [CLAUDE.md](CLAUDE.md) — рабочие правила: устройство проекта, особенности
  исходников, оформление, порядок сборки базы, запуск на устройстве.

## Разбор с ИИ

Единственное, чему нужен интернет. Всё остальное — перевод, поиск, карточки,
карта, параллельные места, слова оригинала — работает в самолёте, как и
обещано.

Модель не вспоминает Писание по памяти: сервер собирает источники из той же
`bible.db` — статьи Никифора по сущностям отрывка, карточки людей и мест,
тексты параллельных мест — и отдаёт их как единственное основание. Ссылки в
ответе собирает сервер из того, что реально ушло в запрос, поэтому выдуманного
источника в списке не появится. Не хватило источников — модель обязана так и
сказать, а не восполнить пробел.

Что защищено и чем:

| Что | Как |
| --- | --- |
| Ключ модели | Остаётся на сервере, в бандл не попадает |
| Кто спрашивает | App Attest: устройство доказывает Apple, что приложение подлинное, и получает пропуск на сутки. Общего секрета в бандле нет |
| Расходы | Кеш ответов (повтор идёт мимо модели), 40 разборов в час и 200 в сутки на устройство, потолок на сутки для всех |
| Живость | Служба в автозапуске плюс сторож: раз в пять минут проверяет, что сервер отвечает, и перезапускает молчащий |
| Канал | HTTPS, сертификат Let's Encrypt продлевается сам. Бэкенд слушает только `127.0.0.1`, наружу его отдаёт Caddy |

Сервер — в [server/](server/), там же его README и конфиги. Адрес
подставляется на сборке:

```bash
flutter build ios --release \
  --dart-define=AI_ENDPOINT=https://holybible-api.eastus.cloudapp.azure.com
```

Без этого определения приложение собирается по-прежнему и честно пишет, что
разбор недоступен, вместо выдуманного ответа.

## Что в базе

`assets/db/bible.db` — 57 МБ, в бандл едет сжатой (18,5 МБ):

- 2 перевода в общественном достоянии — Синодальный и WEB, 62 267 стихов;
- 4259 сущностей: 3142 человека, 1003 места, 114 понятий; у 3964 есть русское
  имя, 1069 мест имеют координаты;
- 53 843 спана упоминаний — по ним работает тап по слову в тексте;
- 9506 связей родства, 341 291 перекрёстная ссылка (OpenBible, CC BY);
- 4581 русская статья из энциклопедии Никифора (1891), 1796 из них привязаны
  к сущностям, остальные образуют словарь;
- векторная основа карты: 97 линий, 1624 точки (Natural Earth, PD).

`assets/db/strongs.db` — 24,5 МБ (8,5 сжатой): 683 871 привязка номеров
Стронга к словам английского текста и 16 195 статей словаря. Открывается
лениво, только когда просят «Слова оригинала».

Источники и лицензии: Синодальный и WEB — public domain; TIPNR (Tyndale House)
— CC BY 4.0; OpenBible.info — CC BY; словарь Стронга в оцифровке openscriptures
— CC BY-SA; энциклопедия Никифора — public domain, получена через API Викитеки;
Natural Earth — public domain. Парсинг чужих сайтов запрещён правилами проекта.

## Как запустить

```bash
flutter pub get
flutter run -d <simulator>
```

На живом устройстве `flutter run` доходит до сборки и падает на установке,
поэтому:

```bash
flutter build ios --release
xcrun devicectl device install app --device <UDID> build/ios/iphoneos/Runner.app
xcrun devicectl device process launch --device <UDID> com.holybible.holyBible
```

UDID — из `xcrun devicectl list devices` (строка со `connected`).

## Как пересобрать базу

Исходники (`data/raw/`) в репозиторий не входят: это чужие выгрузки на 86 МБ.
Без них приложение собирается и работает — готовые `*.db.gz` лежат в
`assets/db/`. Пересборка нужна, только если меняется слой данных, и идёт
строго по порядку — каждый следующий шаг дописывает свой слой в тот же файл,
а первый создаёт базу заново:

```bash
dart run tool/build_bible_db.dart      # текст, FTS5
dart run tool/build_entities.dart      # люди, места, понятия, упоминания, имена
dart run tool/build_cross_refs.dart    # параллельные места
dart run tool/build_articles_ru.dart   # русские статьи и словарь
dart run tool/build_map.dart           # векторная карта
dart run tool/build_strongs_lex.dart   # словарь оригинала
dart run tool/pack_db.dart             # ОБЯЗАТЕЛЬНО: сжатие в *.db.gz
```

Последний шаг обязателен: в бандл едут только сжатые базы. Забыть его — значит
собрать приложение со старыми данными. После пересборки поднимите
`bibleDbVersion` в [lib/data/bible_database.dart](lib/data/bible_database.dart),
иначе у тех, кто уже поставил приложение, останется старая копия.

Русские статьи качаются отдельно и заранее: `dart run tool/fetch_nikifor.dart`
складывает энциклопедию в `data/raw/nikifor/`. Викитека ограничивает частоту
обращений, весь проход занимает около десяти минут.

## Устройство кода

```
lib/
  core/      темы и палитры, дизайн-система (design.dart), разбор ссылок,
             русский стеммер, церковный календарь
  data/      модели и репозитории поверх sqlite3; user.db отдельно
  features/  reader, today, explore, entity, map, search, library, ai
  state/     провайдеры Riverpod
tool/        сборка базы и вспомогательные скрипты
docs/        задание и статус
test/        39 тестов: user.db, разбор ссылок, USFM, календарь
```

Правила, которые легко нарушить по незнанию, собраны в [CLAUDE.md](CLAUDE.md).
Коротко самое важное:

- UI и комментарии — на русском;
- размеры, скругления и типографика берутся из
  [lib/core/theme/design.dart](lib/core/theme/design.dart), а не выдумываются
  заново;
- распознавание сущностей считается на сборке базы, не в рантайме;
- переход к стиху — только через `jumpRequestProvider`;
- любую правку оформления проверять на светлой и тёмной палитре;
- заведомо пустые разделы прячутся за `SHOW_UNRELEASED`: App Store отклоняет
  сборки с placeholder-контентом.

## Что осталось сделать

Перед публикацией, по порядку:

1. **Войти в Xcode под аккаунтом PHARMIQ ACADEMY** (Settings → Accounts).
   Команда `XQ35SJRLQH` уже прописана в проекте, подпись автоматическая.
2. **Обновить сервер.** В `server/privacy.html` вписать почту для связи вместо
   `ПОЧТА_ДЛЯ_СВЯЗИ`, выложить `main.py`, `privacy.html` и
   `deploy/holybible-api.service`, в `~/.holybible.env` поставить
   `APPLE_TEAM_ID=XQ35SJRLQH`. Без этого App Attest отклонит все устройства:
   он сверяет команду, которой подписана сборка.
3. **Проверить App Attest на живом iPhone** сборкой новой команды — заверение
   подписывает настоящее устройство, на сервере это не проверить. Разбор
   заверения покрыт [server/test_attest.py](server/test_attest.py) на
   самодельных ключах. После проверки закрыть запасной путь:
   `ALLOW_APP_TOKEN=0`.
4. **App Store Connect.** Анкета App Privacy — ровно по
   [ios/Runner/PrivacyInfo.xcprivacy](ios/Runner/PrivacyInfo.xcprivacy);
   ссылка на политику — `https://holybible-api.eastus.cloudapp.azure.com/privacy`,
   Support URL — `https://holybible-api.eastus.cloudapp.azure.com/support`;
   скриншоты только для iPhone; сборка через TestFlight:

       flutter build ipa --release \
         --dart-define=AI_ENDPOINT=https://holybible-api.eastus.cloudapp.azure.com

5. Изображения и иконография из Wikimedia (для карточек людей и мест).
6. Святые по дням и раздел «История».

В планах, но не сейчас — сборка под Android и адаптивная иконка. Планы чтения,
маршруты на карте и резервная копия заметок сняты с очереди 19 августа.

## Известные слабые места

- 295 сущностей остались без русского имени — это хвост с одним-четырьмя
  упоминаниями, где не помогают ни текст, ни словарь.
- Часть имён в хвосте списка стоит в косвенном падеже: начальную форму снимает
  словарь Никифора, а его хватает не на всех. Нужна настоящая морфология.
- Английский текст TIPNR остаётся у тех, у кого нет русской статьи; он спрятан
  под «Справка на английском» и не выдаётся за описание.
- Сервер разбора живёт на одной VM: её выключение гасит разбор у всех.
  Остальное приложение при этом работает как обычно.
- Swift-часть App Attest не собиралась ни разу: Xcode нет на машине, где шла
  работа.
- Нет CI; `go_router` и `intl` объявлены в pubspec и не используются.
